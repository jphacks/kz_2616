# 天気背景のデザイン仕様(Apple「天気」アプリ風)

## ゴール
窓の向こうに、**Apple純正の天気アプリのような、グラデーションと穏やかな動きの空**が広がって見えること。
写真のようなリアルさではなく、**滑らかで上品な抽象表現**を目指す。

## 前提と制約(必ず守る)
- **Appleの画像・アイコン・ロゴ・素材は使わない。** 見た目の「雰囲気」だけを、自分たちのコードで表現する
- 描画は、既存の**PixiJS(粒・雲・星・稲光)+ CSSのグラデーション(空の色)**
- 対象端末は**タブレット**。60fpsを目標に、解像度(`resolution`)は最大2にする
- 背景だけを担当する。窓枠・曇り・手書きは触らない
- 新しいライブラリは追加しない

## 重要: 曇りレイヤーとの相性
この背景の上に、白っぽい曇りが重なり、指で拭くと背景が見える。
- 背景が**白すぎると、書いた文字が見えない**。最も明るい部分でも、明度は約85%以下にする
- 背景の**中央〜下部**に、ある程度の濃淡を持たせる
- 動きは穏やかに(速い動きは、雨と雷だけ)

## 時間帯のグラデーション(昼夜の連続変化)
日の出・日没の時刻で、空の色を**なめらかに補間**する(段階的に切り替えない)。

| 時間帯 | 上 → 下 |
|---|---|
| 昼(晴れ) | `#3a8fe0` → `#8cc8f5` |
| 朝焼け・夕焼け(日の出/日没の前後45分) | `#3b5a9d` → `#e8836b` → `#f6c177` |
| 夜(晴れ) | `#0b1535` → `#243b6b` |

- 色の補間は、RGBまたはHSLの線形補間でよい
- 日の出・日没の時刻が取れないときは、`isDay`だけで昼夜を切り替える(クロスフェードはさせる)
- 日の出・日没を使うには`WeatherState`に項目を足す必要がある → **案を示して、リーダーの確認を待つ**。`lib/weather.ts`では、Open-Meteoの`daily=sunrise,sunset`と`timezone=auto`を指定する

## 天気ごとの表現
Open-Meteoの天気コード(WMO)をもとに、次の表現にする。

| 状態 | コード | 背景色(昼 上→下) | 動く要素 |
|---|---|---|---|
| 快晴 | 0 | 昼の晴れ | 太陽のグロー(放射グラデーション、ゆっくり呼吸する程度)。夜は月と、またたく星 |
| 晴れ時々曇り | 1〜2 | 晴れ + 雲 | 薄い雲が数個、ゆっくり流れる |
| 曇り | 3 | `#7d8fa3` → `#b4c0cd` | 柔らかい雲が3層、視差(手前ほど速い)で流れる |
| 霧 | 45, 48 | `#aeb7bf` → `#c9d0d6` | 半透明の帯が2〜3本、横にゆっくり漂う。コントラストは低め |
| 霧雨・雨 | 51〜67, 80〜82 | `#54606e` → `#8793a1` | 斜め(約10度)の雨筋を2〜3層。手前は長くて濃く、奥は短くて薄い |
| 雪 | 71〜77, 85, 86 | `#8a9bb0` → `#c3cfdb` | 丸い雪の粒。大きさ1〜4px、手前の粒はぼかし、横に揺れながらゆっくり落ちる |
| 雷雨 | 95〜99 | `#2c303a` → `#4b4f5c` | 強い雨 + 5〜12秒おきにランダムで稲光(全面が一瞬白く光り、約300msで消える。2回連続で光ることもある) |

- 夜の色は、昼の色を**明度を落として青みを足した**ものにする(例: 雨の夜は`#1e2530` → `#343e4c`)
- 雨の強さ(小雨/強い雨)で、粒の数を変える

## 動きのルール
- 天気が変わるときは、**約1.5秒のクロスフェード**で切り替える
- 雲は、粒ではなく**ぼかした大きな塊**で描く。画面幅を横切るのに、手前の層で約40秒、奥で約90秒
- 粒の上限: 雨150、雪120(タブレットで落ちるときは、さらに減らす)
- ランダム要素は、初期化時に配置して動かす(フレームごとに乱数を作り直さない)
- `document.hidden`のときは、アニメーションを止める。`prefers-reduced-motion`のときは、動きを大幅に減らす

## PixiJSでの注意(重い・壊れやすい点)
- **フィルター(`BlurFilter`など)は重い。** 雲などのぼかしは、オフスクリーンのCanvasにぼかし付きの放射グラデーションを描き、それを**テクスチャにして`Sprite`で使う**
- 粒が多いものは、テクスチャを使い回し、`Sprite`(または`ParticleContainer`)で描く
- Reactの開発時はコンポーネントが2回マウントされる。**初期化の完了前にアンマウントされても、確実に破棄(`destroy`)する**。二重に描画されたり、`WebGL context`が増えないようにする
- 背景は透明(`backgroundAlpha: 0`)にして、空のグラデーションはCSSで下に敷く
- PixiJSのバージョンは`package.json`で確認し、そのバージョンのAPIを使う(v7とv8で初期化の書き方が違う)

## ファイル構成(このフォルダの中に作る)
```
src/components/Window/
├─ WeatherOverlay.tsx     … 入口。今のpropsを維持
└─ weather/
   ├─ weatherCode.ts      … WMOコード → 天気カテゴリ
   ├─ palette.ts          … 天気・時間帯の色、補間の関数
   ├─ effects/            … clouds / rain / snow / stars / lightning / fog(描画ロジック。1ファイル1表現)
   └─ (AGENTS.md / WEATHER_DESIGN.md / CLAUDE.md)
```

## 確認用のデバッグ画面(最初に作る)
`src/app/test/weather/page.tsx`に、次の操作パネルを付ける。
- 天気の選択(快晴 / 晴れ時々曇り / 曇り / 霧 / 小雨 / 強い雨 / 雪 / 雷雨)
- **時刻スライダー**(0〜24時。日の出6:00・日没18:00を仮定して、朝焼け・夕焼けを確認できる)
- 気温スライダー(窓枠の色の確認用)
- 窓の4:3の枠の中に表示し、**曇りレイヤーを重ねるON/OFF**を付けて、文字が読めるか確認する

## 完成の基準
1. 8種類の天気 × 昼・夕方・夜 で、それぞれ違和感のない見た目になる
2. 天気や時刻を切り替えても、ガクッとした色の変化がない
3. タブレット実機で、動きがカクつかない(目安60fps、最低30fps)
4. 曇りレイヤーを重ねて指で拭いたとき、書いた文字がはっきり読める
5. `npm run lint`と`npm run build`が通る

## 進め方(1つ終わるごとに確認してから次へ)
1. デバッグ画面と、天気コードの変換(`weatherCode.ts`)
2. 時間帯のグラデーション(`palette.ts` + クロスフェード)
3. 晴れ・曇り(太陽、月、星、雲)
4. 雨・雪
5. 霧・雷雨
6. 性能の調整(粒の数、停止条件、`prefers-reduced-motion`、PixiJSの破棄の確認)
